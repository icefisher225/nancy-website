# website

This is where my personal website will live.

Static site built with **HTML + CSS + TypeScript**, deployed on **Cloudflare Pages**.

No framework and no bundler. TypeScript is compiled by `tsc` into plain ES
modules the browser loads directly. Pages are hand-authored HTML.

## Structure

```
.
├── public/                 # Cloudflare "Build output directory" (served as-is)
│   ├── index.html          # landing page
│   ├── articles/
│   │   ├── index.html      # article list
│   │   └── hello-world/
│   │       └── index.html  # one article = one folder = clean URL
│   ├── contact/
│   │   └── index.html
│   ├── css/styles.css
│   ├── js/                 # GENERATED by tsc (gitignored, do not edit)
│   └── robots.txt
├── src/
│   └── main.ts             # the TypeScript (nav toggle, etc.)
├── tsconfig.json
├── package.json
└── .gitignore
```

`public/js/` is build output: it is produced by `tsc` and is gitignored.
Cloudflare regenerates it on every deploy.

## Local development

Requires Node.js (for `tsc`) and Python 3 (for the dev server; any static
server works).

```bash
npm install        # one time, installs TypeScript

# Terminal 1: recompile TS on every save
npm run watch

# Terminal 2: serve the site
npm run serve      # http://localhost:8000
```

`npm run build` does a one-off compile. `npm run clean` removes `public/js/`.

### Adding an article

Copy `public/articles/hello-world/` to a new folder, edit its `index.html`,
then add a matching entry to the list in `public/articles/index.html`.

### A note on TypeScript imports

There is no bundler, so the browser resolves imports itself. If you split
`main.ts` into multiple files, local imports need an explicit `.js` extension
(the compiled name), for example `import { x } from "./util.js";`.

## Color scheme (dark mode)

The site **follows the visitor's OS/browser color preference**. Pure CSS, no JS
toggle. All theming is in `public/css/styles.css`.

- OS set to dark -> dark
- OS set to light -> light
- OS unset / unknown -> light

A note on "unknown": browsers do not expose a separate "no preference" state
(`prefers-color-scheme: no-preference` was removed from the spec and never
matches); a user who hasn't chosen reports as light. So there is no way to show
dark to an "unset" user without also overriding users who deliberately chose
light. We follow the system: light is the base, and `@media (prefers-color-scheme:
dark)` overrides to the dark palette. `color-scheme: light dark` themes native
form controls, scrollbars, and the canvas to match (Safari/WebKit requires it
for dark controls).

Verified on Chromium (Chrome/Edge), WebKit (Safari), and Firefox: light and dark
OS settings render the matching theme on all three.

To change the palette, edit the `--light-*` / `--dark-*` tokens at the top of
`styles.css`; everything else references them.

## Deployment (Cloudflare)

The repo is connected to a Cloudflare **Workers Builds** project (modern
Cloudflare provisions "Pages" sign-ups on the Workers platform). Pushing to
`main` deploys to production; any other branch gets a preview URL.

Each build does two steps:

1. **Build command** `npm run build` runs `tsc`, compiling `src/*.ts` into
   `public/js/`.
2. **Deploy command** (`npx wrangler deploy` on `main`,
   `npx wrangler versions upload` on other branches) reads `wrangler.jsonc` and
   uploads the static assets.

`wrangler.jsonc` (at the repo root) is what makes this work. It declares an
assets-only deploy (`assets.directory: "./public"`, no Worker script), so
Cloudflare serves the `public/` directory. Without it, the deploy step fails
with "Missing entry-point to Worker script or to assets directory".

The dashboard build/deploy commands are the Workers Builds defaults, so the
only configuration that lives in this repo is `wrangler.jsonc` plus the
`build` script in `package.json`. Note: a Workers Builds project has no
"Build output directory" field; the deploy target comes from `wrangler.jsonc`.
